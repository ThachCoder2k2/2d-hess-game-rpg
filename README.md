# The Unbound Pawn

A Godot 4 top-down grid action adventure about a white pawn that breaks free from the rules of chess.

**Where things stand:** `docs/where-we-are.md` (status of every area and the decisions waiting
for the owner). **What is being built:** `docs/game-base-plan.md` (the complete-base plan and its
milestones). **How the code works:** `docs/ARCHITECTURE.md`. **Rules for contributors:** `CLAUDE.md`
and `AGENTS.md`.

## Current Milestone

The first playable foundation includes:

- 640x360 pixel-perfect 2D presentation.
- One-cell cardinal movement.
- Buffered and held movement.
- `Shift + direction` turning without movement.
- One-cell Wooden Sword attacks.
- Two-cell Pencil Thrust skill on `Q`.
- Black Pawn AI with diagonal attack telegraphs.
- Enemies move by their own chess law, as data (`MovementConfig.allowed_directions`): Pawn cardinal, Bishop diagonal, Knight L-step.
- Knight enemy with L-shaped unarmed attacks.
- Enemy weapon pickups and pre-armed variants.
- Pencil Spear and Ruler Blade replacement attack patterns.
- Encounter attack token preventing simultaneous strikes.
- Player damage, invulnerability, defeat, and room reset.
- A styled Pawn Ambush playground room.
- TileMapLayer-based board floor with reusable TileSet assets.
- Editor-authored first encounter art, blockers, spawn previews, and pickup previews.
- Draggable room authoring markers for hero start, blockers, enemy spawns, and pickups.
- Real PNG sprite placeholders and AnimationPlayer clips for the hero, Pawns, Knight, pickups, and toy weapons.
- Headless grid-logic tests.

## First run after a fresh clone — build the art

The folders `chess/`, `tiles/`, `maps/`, `rooms/` and `piece_templates/` under
`assets/_generated/` are produced by scripts in `tools/`, so the repository
carries the generators and not their output (the whole folder is gitignored and
never hand-edited). A fresh clone has none of them until you build them, and
Godot will report missing textures if you open the project first. Build them
once, in this order:

```bash
HOME=/tmp/unbound-pawn-godot ../Godot.app/Contents/MacOS/Godot --headless --path . -s tools/generate_chess_sprites.gd
```

```bash
HOME=/tmp/unbound-pawn-godot ../Godot.app/Contents/MacOS/Godot --headless --path . -s tools/generate_kingdom_tiles.gd
```

```bash
HOME=/tmp/unbound-pawn-godot ../Godot.app/Contents/MacOS/Godot --headless --path . -s tools/generate_demo_map.gd
```

```bash
HOME=/tmp/unbound-pawn-godot ../Godot.app/Contents/MacOS/Godot --headless --path . -s tools/generate_stage1_room_art.gd
```

```bash
HOME=/tmp/unbound-pawn-godot ../Godot.app/Contents/MacOS/Godot --headless --path . --editor --quit
```

The last command is Godot's import pass; run it before the tests or the editor sees
the new PNGs. The sprites that used to sit directly in `assets/sprites/generated/`
(now `content/player/body.png`, `content/skills/wooden_sword/icon.png`, ...) are not
generated by anything and are committed as they are (they are source art).

Hand-drawn art is different: `assets/map_pieces/` is source, is committed, and is
never regenerated. Anything you draw and drop in there replaces the procedural
version of that piece on the next build.

`tools/bootstrap_worktree.sh` runs all of the steps above in one command (an import pass,
the four generators, a second import pass). Use it for a fresh clone or a parallel
worktree: `tools/bootstrap_worktree.sh`, with `GODOT_BIN` and `BOOTSTRAP_HOME` to override
the Godot binary and the private `HOME`. It exits 0 only when every step came out clean.
`tools/README.md` describes it and the other build tools.

## Run

Open `project.godot` in Godot 4.6 or run:

```bash
../Godot.app/Contents/MacOS/Godot --path .
```

## Test

The canonical runner is `python3 tools/run_all_tests.py --strict` (this is what `/verify`
runs, see `.claude/commands/verify.md`). It does the import pass, finds every suite by
name (`tests/run_tests.gd`, `tests/*_test.gd`, `tests/**/test_*.gd`), runs each in its own
bounded subprocess, fails on any script error, `FAIL:` line or missing `PASS:` line, and
checks that every `PASS:` label recorded in `tests/baseline_labels.txt` still passes.
The last lines must read `0 failed` and `GREEN`. `python3 tools/run_all_tests.py --self-test`
(and `python3 tools/move_res.py --self-test`) check that the gate itself still fails on a hang,
a script error, a `FAIL:` line, a missing verdict or a vanished label; `/verify` runs both first.
Set `GODOT` to the Godot binary and
`UNBOUND_GODOT_HOME` to a private `HOME` if the defaults do not fit your machine.

To run one suite by hand, with an isolated `HOME`:

```bash
HOME=/tmp/unbound-pawn-godot ../Godot.app/Contents/MacOS/Godot --headless --path . -s tests/run_tests.gd
```

Expect `TESTS COMPLETE: 0 failure(s)` from that one and `... TEST: PASS` from each of the
others. The suites live in `tests/` (the older ones at the top, plus `architecture/`,
`audio/`, `bridge/`, `content/` and `support/`).

## Controls

- `WASD` or arrows: move one cell.
- `Shift + direction`: turn without moving.
- `Space` or `K`: Wooden Sword.
- `Q`: Pencil Thrust.
- `R`: reset the room.
- `B`: open the Book of House Rules.
- `F3`: toggle the debug view. `F11`: fullscreen.

## Project Structure

The simulation is a full ECS (`docs/ARCHITECTURE.md` has the details). Today's folders:

- `scenes/`: the main scene, authored rooms (`rooms/`), the kingdom zone, and UI scenes.
- `objects/`: reusable prefabs: actor views (`ActorView` puppets), markers, world helpers, audio.
- `resources/`: Inspector-tunable `.tres` data for enemies, movement, decisions, attacks, weapons, visuals, difficulty, objectives, Book of House Rules, tiles and the world graph.
- `scripts/ecs/`: the simulation: `EcsWorld`, `EcsGrid`, components, systems, `EcsBoot`, `EcsActorFactory`, `ActorView`, and the `EntityComponent` nodes.
- `scripts/data/`, `scripts/ai/`, `scripts/combat/`: Resource schemas (`EnemyDefinition`, `MovementConfig`, `AttackPattern`, `EnemyWeapon`, ...).
- `scripts/world/`, `scripts/ui/`, `scripts/visuals/`, `scripts/audio/`, `scripts/main.gd`: room markers, board overlay, camera, `WorldState`, HUD, sound, and the bridge from the ECS to presentation.
- `tests/`: headless tests. `tools/`: generators and build scripts (never shipped). `assets/`: raw art and audio.
- `docs/`: architecture, coding standards, the build plan (`game-base-plan.md`), status (`where-we-are.md`), design specs, and `archive/` for superseded documents.

`docs/game-base-plan.md` section 13 describes a planned re-organisation (`content/`, `schema/`, `ecs/`, `authoring/`, `presentation/`, `shell/`). It is a target and is not built yet.
