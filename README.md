# The Unbound Pawn

A Godot 4 top-down grid action adventure about a white pawn that breaks free from the rules of chess.

**Where things stand:** `docs/where-we-are.md` (status of every area and the decisions waiting
for the owner). **What is being built:** `docs/game-base-plan.md` (the complete-base plan and its
milestones). **How the code works:** `docs/ARCHITECTURE.md`. **Rules for contributors:** `CLAUDE.md`
and `AGENTS.md`. **I want to change X, which file do I open?** `docs/OWNER_GUIDE.md`, and then
browse `content/`.

## Current Milestone

The first playable foundation includes:

- 640x360 pixel-perfect 2D presentation.
- One-cell cardinal movement.
- Buffered and held movement.
- `Shift + direction` turning without movement.
- One-cell Wooden Sword attacks.
- Two-cell Pencil Thrust skill on `Q`.
- Black Pawn AI with diagonal attack telegraphs.
- Enemies move by their own chess law, as data (`MovementConfig.allowed_directions`): Pawn cardinal, Bishop diagonal, Knight L-step.
- Knight enemy with L-shaped unarmed attacks.
- Enemy weapon pickups and pre-armed variants.
- Pencil Spear and Ruler Blade replacement attack patterns.
- Encounter attack token preventing simultaneous strikes.
- Player damage, invulnerability, defeat, and room reset.
- A styled Pawn Ambush playground room.
- TileMapLayer-based board floor with reusable TileSet assets.
- Editor-authored first encounter art, blockers, spawn previews, and pickup previews.
- Draggable room authoring markers for hero start, blockers, enemy spawns, and pickups.
- Real PNG sprite placeholders and AnimationPlayer clips for the hero, Pawns, Knight, pickups, and toy weapons.
- Headless grid-logic tests.
- Every chess piece is drawn inside its 32 x 32 cell with a margin, never cell-sized or taller (the
  owner's rule of 2026-10-12): the sizes are `content/feel/piece_sizes.tres`, one actor view
  (`presentation/views/actors/actor_view_base.tscn`) serves the pawn, the black pawns, the knight and the
  bishop, and `assets/_generated/previews/pieces_in_cells.png` shows every piece in its cell.

From M5 the game is a **skeleton you can play from the title to the credits**: the six Stage 1 rooms, the hub and the five districts
(Toybox, Bookshelf, Block Tower, Dollhouse, Under-Bed) as 34 rooms on one world graph (`content/world/world.tres`), five stand-in bosses
whose falls open the hub's doors, and the Desk's last door that ends the run through the ending cards and the credits. Most rooms are
**stubs** (the plan's id, size, shape, doors and a piece of each family, in flat greybox tiles); the guide for the owner's play-through
(gate OG1) is section 9 of `docs/OWNER_GUIDE.md`, `tools/print_world_map.gd` prints the map, `tools/build_room.gd` builds a room from an ASCII
layout, and `docs/route_times.md` is what a bot needs at the least to walk it (`tests/playthrough/test_full_route.gd`).

## First run after a fresh clone

A fresh clone has no class registry (`.godot/`) and none of the generated art, so run one
command first:

```bash
tools/bootstrap_worktree.sh
```

It runs an import pass, the four generators, a second import pass and the actor preview picture
(`assets/_generated/previews/pieces_in_cells.png`), and exits 0 only when every step came out clean
(about 50 s). Set `GODOT_BIN` and `BOOTSTRAP_HOME` to override the Godot
binary and the private `HOME`. `tools/README.md` describes it and the other build tools.

The generators (`tools/generate_chess_sprites.gd`, `generate_kingdom_tiles.gd`, `generate_demo_map.gd`,
`generate_stage1_room_art.gd`) write to `assets/_generated/`: `chess/`, `tiles/`, `maps/`, `rooms/` and
`piece_templates/`. That whole folder is gitignored and never hand-edited, because the repository
carries the generators and not their output. No scene names it any more: the stand-in pictures the
game uses are tracked copies under `content/` (for example `content/rooms/<id>/background.png`),
made by `tools/seed_placeholders.gd`. The sprites that used to sit directly in
`assets/sprites/generated/` (now `content/player/body.png`, `content/skills/wooden_sword/icon.png`, ...)
are not generated by anything and are committed as they are (they are source art).

Hand-drawn art is different: `assets/map_pieces/` is source, is committed, and is never
regenerated. Anything you draw and drop in there replaces the procedural version of that piece on
the next build.

To see which art and audio files are still stand-ins, run
`../Godot.app/Contents/MacOS/Godot --headless --path . -s tools/list_placeholders.gd`. Overwrite a
file (same name, same role) and it leaves the list by itself.

## Run

Open `project.godot` in Godot 4.6 or run:

```bash
../Godot.app/Contents/MacOS/Godot --path .
```

## Test

The canonical runner is `python3 tools/run_all_tests.py --strict` (this is what `/verify`
runs, see `.claude/commands/verify.md`). It does the import pass, finds every suite by
name (`tests/run_tests.gd`, `tests/*_test.gd`, `tests/**/test_*.gd`), runs each in its own
bounded subprocess, fails on any script error, `FAIL:` line or missing `PASS:` line, and
checks that every `PASS:` label recorded in `tests/baseline_labels.txt` still passes.
The last lines must read `0 failed` and `GREEN`. `python3 tools/run_all_tests.py --self-test`
(and `python3 tools/move_res.py --self-test`) check that the gate itself still fails on a hang,
a script error, a `FAIL:` line, a missing verdict or a vanished label; `/verify` runs both first.
Set `GODOT` to the Godot binary and
`UNBOUND_GODOT_HOME` to a private `HOME` if the defaults do not fit your machine.

To run one suite by hand, with an isolated `HOME`:

```bash
HOME=/tmp/unbound-pawn-godot ../Godot.app/Contents/MacOS/Godot --headless --path . -s tests/run_tests.gd
```

Expect `TESTS COMPLETE: 0 failure(s)` from that one and `... TEST: PASS` from each of the
others. The suites live in `tests/` (the older ones at the top, plus `architecture/`,
`audio/`, `bridge/`, `content/`, `playthrough/` and `support/`). Two of them look at the whole game: `tests/playthrough/test_full_route.gd`
plays it from the title to the credits in about 20 seconds (and rewrites `docs/route_times.md` when a measurement changed), and the seven lints
of M5 (`test_preview_before_lethal`, `test_threat_budget`, `test_room_data_audit`, `test_enemy_placement`, `test_layout_archetypes`,
`test_district_loops`, `test_reward_cadence`) hold the rooms to the plan's 7.4 table: each can fail, and a rule a stub room cannot be held to yet
prints a `REPORT` line that says when it becomes a check.

## Controls

Every played action has a keyboard key and a gamepad button (the game follows whichever you touched last, and the hints at the
bottom of the screen show that device's glyphs). The pause menu's Controls panel lists them all, read from the InputMap.

- `WASD` or arrows (pad: left stick or d-pad): move one cell.
- `Shift + direction` (pad: `LB`): turn without moving.
- `Space` or `K` (pad: `A`): Wooden Sword.
- `Q` (pad: `X`): Pencil Thrust.
- `R` (pad: `RB`): call the child (the key exists; the child helps from M10, so it does nothing visible yet).
  Restarting a room is not on `R`: it is Restart Room in the pause menu.
- `Esc` (pad: `Start`): the pause menu: Resume, Book, Settings, Controls (the keys, read from the InputMap), Assist options,
  Restart Room (asks first), Quit to Title (asks first). Settings is also on the title.
- `B`: open the Book of House Rules.
- `F3`: toggle the debug view: the board's debug layer, and the HUD's debug readout (the pawn's cell, who strikes next) in the
  place of the control hints. Off when the game starts. `F11`: fullscreen.

The HUD keeps to two strips (the top 32 px and the bottom 34 px of the 640 x 360 picture), so it never covers a row of the board:
Courage, the skill slot, the enemy count and (from M7c) the Rank badge on top; the status line and the control hints below.
`tools/render_hud_preview.gd` draws it (needs a window) and `docs/ARCHITECTURE.md` ("The HUD: widgets in two strips") explains it.

## Project Structure

The simulation is a full ECS (`docs/ARCHITECTURE.md` has the details and the rule for which folder
may name which). The top-level folders are layers:

- `content/`: **the owner's folder**, data, art, audio and words, with no `.gd` files. `enemies/<id>/`
  (`enemy.tres`, `body.png`, the enemy's own pieces; `_shared/` for the pieces several enemies use),
  `rooms/<id>/room.tscn`, `rules/<id>/page.tres` (the Book of House Rules), `skills/<id>/` (the
  Wooden Sword and Pencil Thrust), `pickups/<id>/`, `player/` (`player.tres`: the pawn's numbers),
  `feel/piece_sizes.tres` (how big each kind of piece is inside its cell), `difficulty/`,
  `world/world.tres` (the world graph), `tilesets/<kit>/`, and `_placeholders.json` (which art and audio
  are still stand-ins).
- `schema/`: the Resource classes that give content its shape (`EnemyDefinition`, `MovementConfig`,
  `AttackPattern`, `EnemyWeapon`, `WorldGraph`, ...).
- `ecs/`: the simulation: `core/` (`EcsWorld`, `EcsGrid`), `components/` (`ecs_components.gd`),
  `systems/<phase>/` (input, decide, move, act, resolve, view).
- `authoring/`: things dragged into a scene: `entity_components/`, `markers/`, the room root, and the
  baker (`EcsBoot`, `EcsActorFactory`).
- `presentation/`: how the world is shown: `views/` (`ActorView`, pickups, the actor scenes), `ui/` (HUD,
  the Book), `board/`, `camera/`, `audio/`, `bridges/` (the event router and the bridges that draw, say or play).
- `shell/`: the game around the game: `app_root.tscn/.gd` (the main scene: the flow, the music, the fade, the
  autosave tick), `title/` and `credits/` (the two screens around the game), `game_root.tscn/.gd` (the in-game
  scene), `game_flow.gd` (the state machine: title, playing, paused, ending, credits; a death or the pause menu's
  Restart Room starts the room again), `bridges/` (the bridges that write the save, rebuild the world or flip a component), `content/`
  (`ContentDb`, the content registry) and `save/` (`SaveService`, the save).
- `assets/`: shared raw art and audio (tile atlases, interface pictures, sound effects, music, the
  hand-drawn bedroom pieces). `tools/`: generators, the test runner and the migration scripts (never
  shipped). `tests/`: headless tests, fixtures and baselines.
- `docs/`: architecture, coding standards, the owner's guide, the build plan (`game-base-plan.md`),
  status (`where-we-are.md`), design specs, and `archive/` for superseded documents.

The folders reached this shape in milestone M1b (`docs/migration-notes.md` records where every file
went); M2 added `shell/content/` (`ContentDb`, the content registry) and `content/feel/`. The plan's tree has
more folders than exist yet (`content/story|audio|ui|...`; `ecs/events/` and `ecs/schedule/` arrived with M3a); they appear
with the milestones that need them.
