# TOOL.5 Spec - Review Checklist Template

**Status:** draft for owner review  
**Linked lane:** Tools And Editor Workflow  
**Checklist gate:** `TOOL.5`

## Purpose

Owner feedback should be structured so fixes are specific and trackable.

## Review Template

```text
Area reviewed:
What feels right:
What feels wrong:
Must fix before acceptance:
Nice to improve later:
Approved? yes/no
```

Full review form:

```text
docs/owner-review-template.md
```

## Completion Requirements

`TOOL.5` can be approved only if every room/feature review can produce clear
accept/fix decisions.

The current template passes this requirement when:

- design feedback can separate approved, rejected, and missing parts,
- editor-scene feedback can identify hidden/script-owned content,
- gameplay-feel feedback can describe readability and fairness,
- art/animation feedback can judge mood and combat clarity,
- audio feedback can judge usefulness and repetition,
- and final owner decisions use explicit approve/revise/block/accept wording.

## Cannot Approve If

- review notes are vague,
- approval state is unclear,
- or fixes cannot be traced to a specific task.
