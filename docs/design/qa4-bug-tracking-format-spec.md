# QA.4 Spec - Bug Tracking Format

**Status:** draft for owner review  
**Linked lane:** QA And Playtesting  
**Checklist gate:** `QA.4`

## Purpose

Make bugs reproducible and fixable.

## Bug Format

| Field | Meaning |
|---|---|
| ID | short bug id |
| Area | room/system |
| Steps | reproduction |
| Expected | intended result |
| Actual | observed result |
| Severity | blocker/major/minor/polish |
| Evidence | screenshot/log/video note |
| Status | open/fixed/verified |

## Completion Requirements

`QA.4` can be approved only if every non-trivial bug can be tracked through fix
and verification.

## Cannot Approve If

- bugs are reported as vibes only,
- severity is unclear,
- or fixes are not verified.
