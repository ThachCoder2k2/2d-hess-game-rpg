# GP.6 Spec - Failure And Checkpoint Rules

**Status:** draft for owner review  
**Linked lane:** Gameplay  
**Checklist gate:** `GP.6`

## Purpose

Failure should encourage experimentation. The player should lose room progress,
not motivation.

## Proposed Rules

| Situation | Result |
|---|---|
| Player courage reaches zero | restart from latest checkpoint/room entry |
| Common room defeat | room resets |
| Boss defeat | boss room resets to phase one |
| Major unlock earned | unlock remains after death |
| Pickups in room | reset unless marked persistent |
| Story progress | major story beats remain |

## Checkpoint Philosophy

Checkpoints should be:

- before bosses,
- at hubs,
- after major rewards,
- and never far from the failed challenge.

## Completion Requirements

`GP.6` can be approved only if:

- the owner accepts low-punishment room reset failure,
- major unlocks persist,
- boss retries are quick,
- and death rules are simple enough to explain in one sentence.

## Cannot Approve If

- death loses too much progress,
- room reset behavior is inconsistent,
- boss retries waste time,
- or failure rules require long explanation.
